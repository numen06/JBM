# 菜单管理分页与多应用多租户模式梳理计划

日期：2026-05-25  
根目录：`D:\workspaces\JBM7`

## 问题结论

用户反馈：菜单管理没有分页，同时需要梳理不同应用、不同租户下的菜单管理模式。

当前判断：

1. 菜单管理无分页是确认 BUG/功能缺口。
2. 应用维度菜单已有后端基础能力：`BaseMenu.appId`。
3. 当前权限查询已有“当前应用菜单 + 平台公共菜单”的模型。
4. 前端菜单管理页没有暴露应用范围、平台菜单/应用菜单边界，也没有租户/组织维度限制。
5. 多租户菜单管理模式需要明确规则，否则后续子应用接入会出现菜单串租户、误改平台菜单、角色授权范围不清等问题。

## 现状分析

### 前端菜单管理

文件：

- `jbm-admin-vue/src/views/system/MenuList.vue`
- `jbm-admin-vue/src/api/menu.ts`

当前 `MenuList.vue`：

- 使用 `listAllMenus()` 一次性拉全量菜单。
- `filteredItems` 在前端本地按 `menuCode/menuName/path` 过滤。
- 没有 `PaginationBar`。
- 没有应用筛选。
- 新建/编辑表单没有 `appId` 字段。

`menu.ts` 其实已有分页方法：

```ts
export async function listMenus(page = 1, size = DEFAULT_PAGE_SIZE) {
  const res = await get<DataPaging<BaseMenu>>('/menu', { params: pageParams(page, size) })
  return unwrap(res)
}
```

但页面没有使用它。

### 后端菜单接口

文件：

- `jbm-cluster/jbm-cluster-platform/jbm-cluster-platform-center/src/main/java/com/jbm/cluster/center/controller/BaseMenuController.java`
- `jbm-cluster/jbm-cluster-common/jbm-cluster-common-mysql/src/main/java/com/jbm/cluster/common/mysql/service/impl/BaseMenuServiceImpl.java`

已有接口：

- `GET /menu`：分页列表，返回 `DataPaging<BaseMenu>`。
- `GET /menu/all?appId=`：全量列表。
- `GET /menu/current`：当前登录应用菜单。
- `POST /menu`：创建菜单。
- `PUT /menu/{menuId}`：更新菜单。
- `DELETE /menu/{menuId}`：删除菜单。

`BaseMenuServiceImpl.findListPage(BaseMenuForm form)` 当前只支持：

- `menuCode likeRight`
- `menuName likeRight`

没有明显支持：

- `path`
- `status`
- `appId`
- 平台菜单 `appId is null`
- 应用菜单 `appId = ?`
- 排序稳定性

### 应用菜单模型

实体：

- `BaseMenu.appId`
- `BaseApp.appId`
- `BaseApp.orgId`

当前含义：

- `base_menu.app_id is null`：平台公共菜单。
- `base_menu.app_id = 当前应用 appId`：指定应用菜单。

权限查询已有类似模型：

`BaseAuthorityMapper.xml`

当 `appId != null`：

```sql
AND (m.app_id = #{appId} OR m.app_id is null)
```

当 `appId == null`：

```sql
AND m.app_id is null
```

这说明系统当前已经承认：

- 平台菜单全局共享。
- 应用菜单只属于指定应用。
- 当前用户菜单 = 当前应用菜单 + 平台公共菜单。

### 多租户/组织边界现状

当前 `BaseMenu` 没有显式 `tenantId` 字段。菜单租户隔离只能通过以下关系间接实现：

```text
租户/组织 -> BaseApp.orgId -> BaseMenu.appId
```

问题：

- 如果菜单管理页面允许任意选择 `appId`，租户管理员可能看到或管理其他租户应用菜单。
- 如果租户管理员能编辑 `appId=null` 的平台菜单，会污染所有应用。
- 如果角色授权页不按 appId/租户过滤，会把其他应用菜单授权出去。

## 目标菜单管理模式

建议 Cursor 按以下模式落地。

### 1. 平台菜单

定义：

- `base_menu.app_id is null`
- 例如：仪表盘、系统管理、用户管理、菜单管理、角色管理、网关管理等后台平台菜单。

权限：

- 只有平台超级管理员可新建、编辑、删除。
- 租户管理员只可查看自己被授权的公共平台菜单，不可修改。

用途：

- 所有应用都可继承展示。
- 当前菜单接口在 appId 场景下应返回“平台菜单 + 当前 app 菜单”。

### 2. 应用菜单

定义：

- `base_menu.app_id = 某个 BaseApp.appId`

权限：

- 平台管理员可管理所有应用菜单。
- 租户管理员只能管理本租户/本组织下应用的菜单。
- 普通用户不可管理菜单。

用途：

- 子应用接入 JBM 后，注册自己的页面/路由/模块菜单。
- 角色授权、当前用户菜单都按当前 appId 聚合。

### 3. 租户/组织隔离

现阶段建议优先使用 `BaseApp.orgId` 作为应用归属边界：

```text
当前登录用户 companyId / org scope -> 可管理 BaseApp.orgId -> 可管理 BaseMenu.appId
```

如果后续已有明确 `tenantId` 模型，可以再把 `tenantId` 落到 `base_menu` 或通过 `base_app.tenant_id` 关联。

短期规则：

- 平台超管：可看到全部平台菜单、全部应用菜单。
- 租户管理员：可看到平台菜单只读 + 本租户应用菜单可编辑。
- 普通用户：不能进入菜单管理。

## 需要修复的功能

### 1. 菜单管理分页

前端：

- `MenuList.vue` 改为使用 `usePagedList` 或等价分页状态。
- 使用 `listMenus(page, pageSize, filters)`。
- 加入 `PaginationBar`。
- 搜索条件提交到后端，不再全量拉取后本地过滤。

API：

- `menu.ts` 的 `listMenus` 支持 filters：
  - `keyword`
  - `menuCode`
  - `menuName`
  - `path`
  - `status`
  - `appId`
  - `scope`

后端：

- `GET /menu` 支持分页条件。
- `BaseMenuServiceImpl.findListPage` 支持 appId/path/status。
- 排序建议：
  - `parent_id asc`
  - `priority asc`
  - `menu_id asc`

### 2. 应用范围筛选

菜单页顶部增加筛选：

- 菜单范围：
  - 平台菜单
  - 指定应用菜单
  - 当前可见菜单
- 应用选择：
  - 来自 `BaseApp` 列表。
  - 租户管理员只能看到本组织/本租户应用。

表格增加列：

- 菜单范围：平台/应用
- 应用名称或 appId

表单增加：

- 菜单范围选择。
- 如果选择应用菜单，必须选择应用。
- 如果选择平台菜单，`appId=null`。

### 3. 平台菜单保护

对 `appId=null` 菜单：

- 非平台超管禁用编辑/删除。
- 删除前检查 `isPersist`，保留菜单不可删除。
- UI 显示“平台公共菜单”标识。

后端也必须校验，不能只靠前端：

- 非平台管理员不能修改 `appId=null` 菜单。
- 非平台管理员不能把应用菜单改成 `appId=null`。
- 非平台管理员不能把菜单绑定到其他租户/组织的应用。

### 4. 角色授权与当前菜单回归

需要确认以下接口的行为：

- `/current/menus`
- `/authority` 或角色授权相关接口
- `BaseAuthorityServiceImpl.findAuthorityMenuByUser`
- `BaseAuthorityMapper.selectAuthorityMenu`

验收规则：

- 当前 appId 不为空时：返回 `appId = 当前应用` + `appId is null`。
- 当前 appId 为空或平台后台：只返回平台菜单，除非平台超管选择管理某个应用。
- 角色授权页只显示当前管理范围内的菜单。

## API 验收

### 分页

调用：

```text
GET /menu?pageForm.currPage=1&pageForm.pageSize=10
```

验收：

- 返回 `contents` 不超过 10。
- 返回 `total`。
- 翻到第二页数据变化。

### 搜索

按编码或名称搜索：

```text
GET /menu?pageForm.currPage=1&pageForm.pageSize=10&menuName=用户
```

验收：

- 只返回匹配菜单。
- 不再由前端全量过滤。

### 应用范围

平台菜单：

```text
GET /menu?...&scope=platform
```

验收：

- 只返回 `appId=null`。

应用菜单：

```text
GET /menu?...&appId=xxx
```

验收：

- 返回指定应用菜单，是否包含平台公共菜单要由 `scope` 明确控制。

建议 scope 定义：

- `platform`：只看平台菜单。
- `app`：只看指定应用菜单。
- `visible`：指定应用菜单 + 平台公共菜单。
