## 问题 1：在线用户没有菜单

### 现象

前端实际已经具备在线用户页面：

- 路由：`jbm-admin-vue/src/router/index.ts`
  - `/system/online-users`
  - 组件：`OnlineUserList.vue`

- 静态导航：`jbm-admin-vue/src/constants/adminNav.ts`
  - 已有 `online-users`
  - `menuCodes: ['onlineUsers']`
  - `to: '/system/online-users'`

但实际菜单仍可能没有出现。

### 根因判断

后端实际初始化类 `AdminVueRbacSeedInitializer` 没有补齐在线用户菜单。

文件：

`jbm-cluster/jbm-cluster-common/jbm-cluster-common-mysql/src/main/java/com/jbm/cluster/common/mysql/init/AdminVueRbacSeedInitializer.java`

当前种子里有：

- users
- roles
- menus
- actions
- orgs
- authority
- apps
- dicts
- extend_fields
- developer_mgmt
- api_key_mgmt
- gateway
- logs

但缺少：

- `onlineUsers`

而前端菜单 store 是根据后端 `/current/menus` 返回的菜单路径和 `menuCode` 过滤静态导航：

`jbm-admin-vue/src/stores/menu.ts`

所以后端没有 `onlineUsers` 菜单权限时，管理员侧栏不会显示在线用户入口。

### 修复建议

在 `AdminVueRbacSeedInitializer` 中补齐：

- `MENU_ONLINE_USERS` 常量，例如 `114L`，注意不要和现有 ID 冲突。
- `seedMenusAndAuthorities()` 中加入：
  - parent：`MENU_SYSTEM`
  - code：`onlineUsers`
  - name：`在线用户`
  - path：`/system/online-users`
  - priority：建议放在用户管理后面。
- `grantSuperAdminAllAuthorities()` 中加入 `MENU_ONLINE_USERS`。

同时建议保留前端已有别名：

`/system/online-users/index -> /system/online-users`

这样兼容历史菜单数据。

### 在线用户按钮权限

当前页面按钮判断：

`jbm-admin-vue/src/views/system/OnlineUserList.vue`

- `hasAction('monitor:online:forceLogout')`
- `hasAction('monitor:online:logout')`

后端接口注解：

`jbm-cluster/jbm-cluster-platform/jbm-cluster-platform-auth/src/main/java/com/jbm/cluster/auth/controller/OnlineUserController.java`

- `@SaCheckPermission("ACTION_monitor:online:forceLogout")`
- `@SaCheckPermission("ACTION_monitor:online:logout")`

建议在 `AdminVueRbacSeedInitializer` 里同时补齐两个 action：

- actionCode：`monitor:online:forceLogout`
- actionName：`在线用户-踢出`
- menuId：`MENU_ONLINE_USERS`

- actionCode：`monitor:online:logout`
- actionName：`在线用户-注销`
- menuId：`MENU_ONLINE_USERS`

并把 action authority 授权给超级管理员。

## 问题 2：有用户登录但在线用户数量统计为 0

### 现象

在线用户列表和仪表盘统计使用的数据源不一致。

在线用户列表：

`jbm-cluster/jbm-cluster-platform/jbm-cluster-platform-auth/src/main/java/com/jbm/cluster/auth/controller/OnlineUserController.java`

它读取：

```java
redisService.keys(JbmCacheConstants.ONLINE_TOKEN_KEY + "*")
```

也就是：

```text
online_tokens:{token}
```

这些数据由登录监听器写入：

`jbm-cluster/jbm-cluster-platform/jbm-cluster-platform-auth/src/main/java/com/jbm/cluster/auth/listener/UserActionListener.java`

```java
redisService.setCacheObject(JbmCacheConstants.ONLINE_TOKEN_KEY + tokenValue, userOnline, ...)
```

但仪表盘统计：

`jbm-cluster/jbm-cluster-platform/jbm-cluster-platform-center/src/main/java/com/jbm/cluster/center/controller/BaseUserController.java`

当前使用：

```java
List<String> online = StpUtil.searchTokenValue("", -1, 0, true);
stats.setOnlineUser((long) online.size());
```

这和在线列表不是同一套来源。Auth 服务写入的是 `online_tokens:*`，Center 直接查本服务 Sa-Token token 搜索，在分布式服务场景下可能查不到 Auth 写的在线表，因此出现登录用户存在但统计为 0。

### 根因判断

确认 BUG：分布式服务下，在线用户数量统计不应使用 Center 本地 `StpUtil.searchTokenValue` 作为唯一来源。应与在线用户列表统一，以 Redis `online_tokens:*` 作为在线用户事实来源。

### 修复建议

在 Center 的 `BaseUserController#getUserStatistics()` 中，在线用户数量改为统计 Redis：

- 注入 `RedisService`
- 使用 `JbmCacheConstants.ONLINE_TOKEN_KEY + "*"` 查询 key 数量
- 排除空对象或过期对象，最好复用在线用户列表同样的有效性判断

建议至少实现：

```java
Collection<String> onlineKeys = redisService.keys(JbmCacheConstants.ONLINE_TOKEN_KEY + "*");
stats.setOnlineUser((long) onlineKeys.size());
```

更稳妥实现：

- 遍历 key
- `redisService.getExpire(key) > 0`
- `redisService.getCacheObject(key) != null`
- 只统计有效记录

这样 `/user/statistics.onlineUser` 与 `/online/pageList.total` 一致。
