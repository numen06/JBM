# 组织新建保存乱码修复计划

日期：2026-05-25  
根目录：`D:\workspaces\JBM7`

## 问题结论

用户反馈：组织管理中新建保存后出现乱码。

这个问题不能只判断为前端显示问题。当前代码里已经发现一个明确风险：项目存在 `V16__base_org_utf8mb4.sql`，说明之前已经意识到 `base_org` 在部分环境可能是 latin1 或非 UTF-8；但该迁移文件本身的中文内容已经显示为乱码，可能会继续把错误的“默认组织”写入数据库。

因此 Cursor 需要按完整链路排查：

页面输入中文 -> 前端 JSON 请求 -> Gateway 转发 -> Center 反序列化 -> MyBatis/JDBC -> MySQL 表/列字符集 -> API 返回 -> 前端渲染。

## 并行执行与统一总测约束

当前会有多个 Cursor 任务并行修改代码。为避免互相抢端口、重启服务、清理测试数据，本计划只负责代码修复、局部构建和记录验证用例。

## 需要先复现并定位乱码发生层

Cursor 先不要盲修。先执行一次复现：

1. 管理员登录。
2. 进入 `/system/orgs`。
3. 新建组织：
   - 组织名称：`测试组织UTF8`
   - 父级留空或选默认组织。
4. 保存后刷新页面。
5. 调接口 `/baseOrg/pageList` 查询这条记录。
6. 直接查数据库 `base_org.org_name`。

判断：

- 如果浏览器请求 payload 已经乱码：查前端输入/测试脚本编码。
- 如果 payload 正常，但响应乱码且数据库正常：查响应 Content-Type/Gateway/前端解码。
- 如果 payload 正常，但数据库已乱码：查 JDBC URL、MySQL 表/列字符集、连接 collation。
- 如果默认组织一直乱码：优先查 Liquibase `V16__base_org_utf8mb4.sql` 和历史脏数据。

## 修复建议

### 1. 修复 Liquibase 文件自身编码

文件：

`jbm-cluster/jbm-cluster-common/jbm-cluster-common-mysql/src/main/resources/db/cluster-rbac/changes/V16__base_org_utf8mb4.sql`

需要确保保存为 UTF-8，并把中文改成真实内容：

```sql
-- 确保 base_org 使用 utf8mb4，避免中文 org_name 在 latin1 环境下乱码
UPDATE base_org SET org_name = '默认组织' WHERE id = 1 AND org_name <> '默认组织';
```

注意：如果这个 changeset 已经在当前数据库标记执行过，仅修改旧文件不会自动重跑。需要另加新的幂等 changeset，例如 `V17__repair_base_org_utf8_data.sql`。

### 2. 增加新的幂等数据修复迁移

建议新增：

`V17__repair_base_org_utf8_data.sql`

内容方向：

- 确认 `base_org` 表使用 `utf8mb4_unicode_ci`。
- 修复默认组织 id=1 为 `默认组织`。
- 可选：修复已知乱码值，但不要误伤真实业务数据。

如果数据库里已有乱码测试组织，建议 Cursor 用脚本或 SQL 清理测试数据，不要把所有疑似乱码都强制替换。

### 3. 检查 JDBC/MySQL 连接编码

当前仓库本地 yml 里没有直接看到 jaja7 的 MySQL URL，可能来自 Nacos `db.properties`。

Cursor 需要检查：

- Nacos `db.properties`
- 本地启动脚本实际加载的 datasource
- `logs/ops-start-center.log` 中 datasource 连接信息

JDBC URL 应包含或等价具备：

```text
useUnicode=true
characterEncoding=utf8
connectionCollation=utf8mb4_unicode_ci
```

如果使用 MySQL 8，建议统一：

```text
characterEncoding=utf8
connectionCollation=utf8mb4_unicode_ci
```

### 4. 检查请求/响应 UTF-8

前端 `org.ts` 走 JSON POST，正常情况下 Axios/fetch 会用 UTF-8。仍需检查：

- `jbm-admin-vue/src/api/request.ts`
- 请求头是否为 `Content-Type: application/json;charset=UTF-8`
- Gateway 是否改写或丢失 charset
- Center 响应 `Content-Type` 是否为 `application/json;charset=UTF-8`

### 5. 不要用错误编码的 PowerShell 写中文测试数据

之前字段管理测试中出现过中文测试数据乱码。Cursor 写中文自动化脚本时：

- Node/Playwright 脚本文件必须 UTF-8。
- 不要用非 UTF-8 PowerShell inline 直接注入中文。
- 页面专项测试可用 `测试组织UTF8`，并保存脚本为 UTF-8。

1. 调 `/baseOrg/save` 新建：

```json
{
  "baseOrg": {
    "orgName": "测试组织UTF8",
    "status": 1,
    "sort": 0
  }
}
```

2. 调 `/baseOrg/pageList` 查询：

```json
{
  "baseOrg": {
    "orgName": "测试组织UTF8"
  },
  "pageForm": {
    "currPage": 1,
    "pageSize": 20
  }
}
```

验收：

- 响应 JSON 中 `orgName` 必须是 `测试组织UTF8`。
- 数据库 `base_org.org_name` 必须是 `测试组织UTF8`。
- 默认组织必须显示为 `默认组织`，不能是乱码。
