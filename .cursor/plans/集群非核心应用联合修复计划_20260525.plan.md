# JBM 集群非核心应用联合修复计划

日期：2026-05-25  
根目录：`D:\workspaces\JBM7`  
执行方：Cursor

## 范围

已完成主链路修复的三核心应用先保持稳定：

- `jbm-cluster-platform-auth`
- `jbm-cluster-platform-center`
- `jbm-cluster-platform-gateway`

本轮纳入联调的非核心平台应用：

| 服务 | 模块 | 当前默认端口 | 入口类 | 主要职责 |
|---|---|---:|---|---|
| Doc | `jbm-cluster-platform-doc` | `9999` | `com.jbm.cluster.doc.JbmDocApplication` | 文档、文件、MinIO/WPS 回调 |
| Push | `jbm-cluster-platform-push` | `3313` | `com.jbm.cluster.push.JbmPushApplication` | 站内信、短信、邮件、MQTT、Webhook |
| Logs | `jbm-cluster-platform-logs` | `3312` | `com.jbm.cluster.logs.JbmLogsApplication` | 业务日志、网关日志、集群访问记录 |
| Job | `jbm-cluster-platform-job` | `4444` | `com.jbm.cluster.job.JbmJobApplication` | 定时任务、Drools、流程执行 |
| Weixin | `jbm-cluster-platform-weixin` | `3319` | `com.jbm.cluster.weixin.miniapp.JbmWxApplication` | 微信小程序、公众号、菜单、模板消息 |
| Bigscreen | `jbm-cluster-platform-bigscreen` | `3314` | `com.jbm.cluster.bigscreen.JbmBigscreenApplication` | 大屏视图上传、清理、预览 |

`jbm-cluster-platform-ai` 当前只有 `bin/target`，不在 `jbm-cluster-platform/pom.xml` modules 中，也没有源码目录。先按历史产物处理，不纳入本轮修复；如要恢复，单独开计划补 pom/source/config。

## 已发现的共性缺口

1. 非核心服务基本没有 `bootstrap-jaja7.yml`，本地联调会落到默认 `bootstrap.yml` 或 `jaja`，Nacos、DB、Redis、MQ、MinIO 等依赖不一定与 `jbm7` 命名空间一致。
2. `jbm-cluster-platform-gateway/src/main/resources/bootstrap-jaja7.yml` 目前只配置 Center/Auth 静态路由，非核心服务经 Gateway 无法转发。
3. `scripts/jbm_cluster_ops.py` 的 `SERVICES` 只包含 `auth/center/gateway/vue`，不能统一启动、等待、停止 Doc/Push/Logs/Job/Weixin/Bigscreen。
4. `JbmClusterConstants.LOG_SERVER` 是 `jbm-cluster-platform-log`，但实际模块和 `BusinessLogClient` 使用 `jbm-cluster-platform-logs`。需要确认是否还有调用方依赖旧名字，建议统一为复数服务名。
5. 非核心服务有较多外部依赖，不能把“启动失败”全部当业务 BUG：MinIO、MQTT、短信、邮件、微信凭证、OpenObserve 等缺失时应降级为可配置、可关闭、可 mock 的 jaja7 行为。

## 执行原则

- 先修 common/node/profile/gateway/ops 这些横向问题，再逐个服务修业务启动和接口问题。
- 不回退三核心应用已经验证通过的修复；需要改 Gateway 时只做路由、Feign URL、白名单等 jaja7 联调补齐。
- 每个服务都要有最小验证闭环：`compile` 通过、可启动或明确外部依赖阻塞、`/actuator/health` 有结果、至少一个经 Gateway 的关键接口有断言。
- 外部三方能力不要在本地冒烟里真实发送：短信、邮件、微信、MQTT、Webhook 默认走 dry-run/mock 或只验证参数与权限。
- 所有新增测试数据使用唯一前缀，如 `cluster_ext_<timestamp>`，避免污染已有 E2E 数据。

## P0：横向修复

### 1. 补齐 jaja7 配置矩阵

为以下模块新增或修正 `src/main/resources/bootstrap-jaja7.yml`：

- `jbm-cluster-platform-doc`
- `jbm-cluster-platform-push`
- `jbm-cluster-platform-logs`
- `jbm-cluster-platform-job`
- `jbm-cluster-platform-weixin`
- `jbm-cluster-platform-bigscreen`

配置要求：

- 使用 `jbm7` namespace、`DEFAULT_GROUP`，与 Auth/Center/Gateway 保持一致。
- `server.port` 保持默认端口，除非本地冲突。
- `spring.application.name` 必须等于实际服务名和 Feign 常量。
- 共享配置按最小依赖引入：`common.properties`、`redis.properties`、`db.properties`、`rabbitmq.properties` 等按服务需要添加。
- 三方依赖加开关，jaja7 默认不因缺少真实凭证导致启动失败。

### 2. 统一服务名与 Feign

重点检查：

- `jbm-cluster-core/src/main/java/com/jbm/cluster/core/constant/JbmClusterConstants.java`
- `jbm-cluster-api-basic/src/main/java/com/jbm/cluster/api/client/BusinessLogClient.java`
- `jbm-cluster-api-basic/src/main/java/com/jbm/cluster/api/service/feign/**`
- 各服务 `@EnableFeignClients` 配置

建议先把 `LOG_SERVER` 修正为 `jbm-cluster-platform-logs`，再全局搜索 `jbm-cluster-platform-log`，确认没有 Nacos 配置或旧客户端仍依赖单数名字。

### 3. 扩展 Gateway jaja7 路由

在 `jbm-cluster-platform-gateway/src/main/resources/bootstrap-jaja7.yml` 增加本地静态路由：

| route id | uri | Path |
|---|---|---|
| `jaja7-doc-local` | `http://127.0.0.1:9999` | `/baseDoc/**,/baseDocGroup/**,/baseDocToken/**,/v1/3rd/file/**,/put,/upload,/get/**,/download/**,/remove/**,/getViewUrl` |
| `jaja7-push-local` | `http://127.0.0.1:3313` | `/pushMessage/**,/notification/**,/pushConfigInfo/**,/emailPushConfig/**,/pushItem/**,/webhookTask/**,/webhookEventConfig/**,/pin/**` |
| `jaja7-logs-local` | `http://127.0.0.1:3312` | `/businessLog/**,/GatewayLogs/**,/clusterAccess/**` |
| `jaja7-job-local` | `http://127.0.0.1:4444` | `/sysJob/**,/sysJobLog/**,/droolsRule/**,/process/**,/workflowDefinition/**,/dynamicField/**,/dynamicClass/**,/ruleOperationLog/**` |
| `jaja7-weixin-local` | `http://127.0.0.1:3319` | `/mp/**,/wx/menu/**,/portal/**,/user/**,/media/**` |
| `jaja7-bigscreen-local` | `http://127.0.0.1:3314` | `/view/**,/bigscreenView/**` |

同时补齐 `spring.cloud.openfeign.client.config`：

- `jbm-cluster-platform-doc.url=http://127.0.0.1:9999`
- `jbm-cluster-platform-push.url=http://127.0.0.1:3313`
- `jbm-cluster-platform-logs.url=http://127.0.0.1:3312`
- `jbm-cluster-platform-job.url=http://127.0.0.1:4444`
- `jbm-cluster-platform-weixin.url=http://127.0.0.1:3319`
- 如新增常量再同步 Bigscreen。

注意：Weixin 的 `/user/**` 与 Center 的 `/user/**` 路由冲突，不能直接放在 Gateway 根路径抢占。建议给 Weixin 增加网关前缀（例如 `/weixin/user/**`）或只保留不冲突的 `/mp/**,/wx/**,/portal/**,/media/**`；如果要保留原控制器路径，Gateway 需要明确排序和 strip prefix，避免影响 Center 用户接口。

### 4. 扩展运维脚本

修改 `scripts/jbm_cluster_ops.py`：

- `SERVICES` 增加 `doc/push/logs/job/weixin/bigscreen`。
- 支持 `python scripts\jbm_cluster_ops.py start auth center gateway logs --background --clean`。
- `wait` 支持按服务列表探活，不再默认只等核心三服务。
- `cleanup/stop` 按端口和 mainClass 精准清理，不误杀非本项目 Java 进程。
- 日志输出到 `logs/ops-start-<service>.log`。

## P1：按服务修复与冒烟

### Logs

目标：

- 启动通过，`/actuator/health` 可访问。
- `BusinessLogClient` 可通过 Feign 调到 Logs。
- 经 Gateway 调用 `/businessLog/demo` 或 `/businessLog/query` 有明确结果。
- `/GatewayLogs/findLogs`、`/clusterAccess/getClusterAccessInfo` 能返回空列表或结构化结果。

重点风险：

- 服务名单复数/单数不一致。
- OpenObserve、IP2Region、DB 表结构缺失。
- 日志查询实体继承列与真实表列不一致。

### Push

目标：

- 启动通过，禁用真实短信/邮件/MQTT 发送。
- `/pushMessage/pageList`、`/pushMessage/findCurrMessagePage` 可查。
- `/notification/send/email`、`/notification/send/sms` 在 dry-run 下返回成功或明确 mock 结果。
- `PushMessageController` 写入消息后，当前用户能查到消息，tenant/user 上下文正确。

重点风险：

- 邮件、短信、MQTT 配置缺失导致 bean 初始化失败。
- Feign 到 Center/Weixin 时缺 Id-Token 或 URL 未配置。
- 用户消息读未读状态跨租户可见。

### Doc

目标：

- 启动通过；MinIO/WPS 缺失时可降级。
- `/baseDoc/pageList` 可查。
- `/baseDocGroup/createTempGroup`、`/baseDocGroup/findGroupItemByToken` 可形成最小闭环。
- 文件上传接口可以使用 mock/minimal 文件，失败时错误信息清晰且不 500 空栈。

重点风险：

- MinIO 配置强依赖。
- `DocumentController` 根路径接口与 Gateway 路由过宽，可能误转发。
- 文件路径参数包含中文或斜杠时编码、XSS、路径解析异常。

### Job

目标：

- 启动通过；定时任务默认不自动执行危险任务。
- `/sysJob/test` 或 `/sysJob` 查询类接口通过。
- `/process/selectPageList`、`/droolsRule/parseAndExecuteRule` 做最小 mock 数据验证。
- 通过 Feign `DroolsRuleServiceClient`、`ProcessServiceClient` 验证服务互信。

重点风险：

- Quartz/ShedLock/Redis/DB 表缺失。
- Drools/Groovy 版本冲突或 Spring Bean 初始化失败。
- 手动 run 任务可能触发外部副作用，冒烟脚本禁止真实执行生产任务。

### Weixin

目标：

- 启动通过；jaja7 无真实 appid/secret 时不阻塞。
- `/mp/sign/getSignature` 对缺配置返回可解释错误。
- `/mp/templateMsg/sendTemplateMsg`、菜单接口默认 dry-run/mock。
- 与 Push 的 `WeixinMpClient` Feign 互通。

重点风险：

- Gateway `/user/**` 路由冲突。
- 真实微信 SDK 凭证缺失。
- XML/UTF-8 响应被 Gateway 过滤器破坏。

### Bigscreen

目标：

- 启动通过。
- `/view/{view}` 返回页面或模板。
- `/bigscreenView/isUpload`、`/bigscreenView/cleanView` 有明确结果。
- 上传视图接口使用临时目录，避免写入不可控路径。

重点风险：

- 静态资源目录、上传路径不存在。
- 文件名中文或特殊字符导致编码/路径问题。

## P2：统一测试脚本

新增脚本建议：

- `scripts/run_cluster_apps_smoke_tests.py`
- 配置文件：`scripts/cluster_apps_smoke_modules.json`
- 输出目录：`docs/testing/cluster-apps-jaja7/`
- 机器可读结果：`.cursor/cluster-apps-smoke-result.json`

脚本流程：

1. 登录 Auth 获取 admin Bearer token。
2. 探测核心三服务和本轮指定非核心服务健康。
3. 经 Gateway 访问各服务只读接口。
4. 对 dry-run 写接口执行最小请求。
5. 验证未携带 token 返回 401 或约定错误。
6. 验证携带伪造 `X-Internal-Service` 不能绕过鉴权。
7. 输出每个服务的 passed/failed/skipped 和失败原因。

## 验收标准

- 六个非核心服务 Maven compile 通过。
- 能通过 `jbm_cluster_ops.py` 选择性启动/停止/等待。
