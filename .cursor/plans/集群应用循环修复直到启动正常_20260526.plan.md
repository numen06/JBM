## P0：构建循环

目标模块：

```powershell
$mods = "jbm-cluster/jbm-cluster-platform/jbm-cluster-platform-auth,jbm-cluster/jbm-cluster-platform/jbm-cluster-platform-center,jbm-cluster/jbm-cluster-platform/jbm-cluster-platform-gateway,jbm-cluster/jbm-cluster-platform/jbm-cluster-platform-doc,jbm-cluster/jbm-cluster-platform/jbm-cluster-platform-push,jbm-cluster/jbm-cluster-platform/jbm-cluster-platform-logs,jbm-cluster/jbm-cluster-platform/jbm-cluster-platform-job,jbm-cluster/jbm-cluster-platform/jbm-cluster-platform-bigscreen"
mvn -pl $mods -am -DskipTests compile
```

循环规则：

1. 如果 compile 失败，只修第一个阻断性编译错误或同类批量错误。
2. 修完后先对相关模块局部 compile，再跑目标矩阵 compile。
3. 编译错误优先级：
   - 服务名常量/Feign 引用不一致
   - 缺少依赖或 scope 错误
   - Spring Boot 2.6 / Cloud 2021 API 不兼容
   - Lombok/泛型/实体字段类型错误
   - 测试源码错误不阻断主启动时，先用 `-DskipTests`，不要扩大范围修测试

退出条件：

- 目标模块 `mvn ... compile` 返回 0。

## 根因分类与修复策略

### 1. jaja7 配置缺失

表现：

- 连接到旧 Nacos namespace。
- 使用 `nacos2:8848`、`nacos-standalone` 或旧 `jaja` 配置。
- 找不到 DB/Redis/MQ 配置。

修复：

- 为目标服务补 `bootstrap-jaja7.yml`。
- 统一 namespace `jbm7`，group `DEFAULT_GROUP`。
- 必要时补 `spring.cloud.nacos.config.shared-dataids`。
- 不把真实生产地址写入 jaja7。

### 2. 外部依赖强初始化

表现：

- MinIO、MQTT、短信、邮件、OpenObserve、Drools、Quartz 初始化失败。

修复：

- jaja7 默认使用 mock/dry-run/disabled。
- 配置缺失时 bean 不应启动失败，改为首次调用返回明确错误。
- 对真实发送类接口增加 dry-run 路径，smoke 不触发真实外部发送。

### 3. 服务名 / Feign URL 错误

表现：

- `No servers available for service`
- `UnknownHostException`
- Feign 找 `jbm-cluster-platform-log` 而实际是 `jbm-cluster-platform-logs`

修复：

- 统一 `JbmClusterConstants` 和 `@FeignClient` 名称。
- `application-jaja7.yml` / `bootstrap-jaja7.yml` 增加本地 URL 覆盖。
- 确保 Gateway `metadata.serviceId` 与 Feign 服务名一致。

### 4. Gateway 路由冲突

表现：

- Center `/user/**` 被非核心服务抢走。
- Auth `/oauth2/**` 路由异常。
- Gateway 404/502，但服务直连健康。

修复：

- 非核心服务避免占用 Center/Auth 根路径。
- 对有冲突的服务使用明确前缀或更窄 Path。
- Weixin 本轮排除，不要为了 `/user/{appid}` 破坏 Center `/user/**`。

### 5. 鉴权和互信失败

表现：

- 直连服务可用，经 Gateway 401/403。
- Feign 调 Center/Auth 返回服务认证失败。
- 伪造 `X-Internal-Service` 被放行。

修复：

- 沿用已修复的 Id-Token/API Key 双通道。
- Gateway 转发保留 `Satoken-Id-Token`、`X-Internal-Service`、`X-Gateway-Api-Key-Id` 等可信上下文。
- 无 token、坏 Bearer、伪造内部 Header 必须失败。

## P1：服务最小可用检查

### Doc

必须：

- 直连 `http://127.0.0.1:9999/actuator/health` OK。
- 经 Gateway 至少验证 `/baseDoc/pageList` 或等价只读接口。
- MinIO/WPS 缺失不影响启动。

### Push

必须：

- 直连 `http://127.0.0.1:3313/actuator/health` OK。
- 经 Gateway 验证 `/pushMessage/pageList` 或 `/pushMessage/findCurrMessagePage`。
- 短信、邮件、MQTT 不真实发送。

### Logs

必须：

- 直连 `http://127.0.0.1:3312/actuator/health` OK。
- 经 Gateway 验证 `/businessLog/query` 或 `/GatewayLogs/findLogs`。
- `BusinessLogClient` 服务名与实际 Logs 服务一致。

### Job

必须：

- 直连 `http://127.0.0.1:4444/actuator/health` OK。
- 经 Gateway 验证 `/sysJob/test` 或查询类接口。
- 不自动执行真实任务，不触发外部副作用。

### Bigscreen

必须：

- 直连 `http://127.0.0.1:3314/actuator/health` OK。
- 经 Gateway 验证 `/view/{view}` 或 `/bigscreenView/isUpload`。
- 上传/清理路径使用本地临时目录或明确配置。
