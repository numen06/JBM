# JBM 集群服务间互信认证机制

## 一、整体架构

```
┌─────────────────┐         ┌─────────────────┐         ┌─────────────────┐
│   Push 服务      │         │   目标服务        │         │     Redis       │
│  (调用方)        │ ──HTTP──>│  (被调用方)      │<──读写──>│   (共享存储)     │
│                 │         │                 │         │                 │
│ JbmFeignRequest │         │SaOAuthFilter    │         │ ClientToken     │
│ Id-Token 生成   │         │AuthStrategy     │         │ Id-Token        │
└─────────────────┘         └─────────────────┘         └─────────────────┘
```

服务间互信基于 **Sa-Token 的 Id-Token（服务端凭证）** 和 **OAuth2 ClientToken** 机制实现，所有服务共享同一个 Redis 实例来存储和验证 Token。

---

## 二、Token 类型说明

| Token 类型 | 用途 | 有效期 | 存储位置 |
|---|---|---|---|
| **Id-Token** | 服务间互信凭证，标识服务身份 | 默认 7 天 (`sa-token.id-token-timeout`) | Redis |
| **ClientToken** | OAuth2 客户端凭证，封装了 Id-Token | 本地 Caffeine 缓存 24 小时 | 本地缓存 + Redis |
| **AccessToken** | 用户登录凭证 | 默认 24 小时 (`sa-token.timeout`) | Redis |

## 三、认证流程详解

### 3.1 调用方（发起请求的服务）

#### 3.1.1 ClientToken 生成

入口：`JbmNodeOAuth2TemplateImpl.generateClientToken()`

```java
// JbmNodeOAuth2TemplateImpl.java
public ClientTokenModel generateClientToken(String clientId, String scope) {
    return clientTokenModelLoadingCache.get(clientId);
}
```

缓存加载器调用 `super.generateClientToken()`，其中 `randomClientToken()` 使用 `SaIdUtil.getToken()` 生成 Id-Token：

```java
// JbmNodeOAuth2TemplateImpl.java
public String randomClientToken(String clientId, String scope) {
    final String idToken = SaIdUtil.getToken();
    return idToken;
}
```

> **关键点**：Id-Token 由 Sa-Token 框架自动管理，每个服务实例启动时自动生成，写入 Redis。

#### 3.1.2 请求构建与 Token 注入

入口：`JbmFeignRequest.buildRequest()`

当 URL 以 `feign://` 开头时，`JbmRequestTemplate` 路由到 `JbmFeignRequest`，在其 `buildRequest` 方法中注入认证信息：

```java
// JbmFeignRequest.java
public Request.Builder buildRequest(Request.Builder httpRequest) {
    SaOAuth2Template saOAuth2Template = SpringUtil.getBean(SaOAuth2Template.class);
    ClientTokenModel clientTokenModel = saOAuth2Template.generateClientToken(
        SpringUtil.getApplicationName(), "*"
    );
    final String authorization = SaManager.getConfig().getTokenPrefix() + " " + clientTokenModel.clientToken;
    httpRequest.header(JbmSecurityConstants.AUTHORIZATION_HEADER, authorization);
    return httpRequest;
}
```

同时，`JbmFeignRequest.buildUrl()` 负责将 `feign://service-name/path` 通过服务发现（Nacos + LoadBalancer）解析为真实地址 `http://ip:port/path`。

#### 3.1.3 URL 路由机制

`JbmRequestTemplate.findCustomizeRequest()` 根据 URL 前缀选择请求实现：

| URL 前缀 | 实现类 | 是否携带认证 |
|---|---|---|
| `feign://` | `JbmFeignRequest` | 携带 Authorization (ClientToken) |
| `http://` / `https://` | `JbmHttpRequest` / `JbmHttpsRequest` | **不携带认证** |

> **注意**：如果数据库中配置的 Webhook URL 使用 `http://` 而非 `feign://`，将无法注入认证信息，导致 401。

---

### 3.2 接收方（被调用的服务）

#### 3.2.1 认证过滤器

入口：`SaOAuthFilterAuthStrategy.run()`

认证流程如下：

```
请求到达
  │
  ├─ 是否本机 IP？ ──是──> 直接放行
  │
  ├─ StpUtil.getTokenValue() 获取 Token
  │    │
  │    ├─ Token 为空？ ──是──> 抛出异常 "无效Token" → 401
  │    │
  │    ├─ StpUtil.getTokenInfo() 检查是否为已登录用户
  │         │
  │         ├─ isLogin=true → 检查是否过期 → 过期则 "Token已失效" → 401
  │         │                 → 未过期则放行
  │         │
  │         └─ isLogin=false → 检查请求 header 中是否有 Satoken-Id-Token
  │                              │
  │                              ├─ 有 → SaIdUtil.checkCurrentRequestToken() → 放行
  │                              │
  │                              └─ 没有 → 继续 OAuth2 校验 ↓
  │
  ├─ SaOAuth2Util.getAccessToken(tokenValue) 查找 AccessToken
  │    │
  │    └─ 找到 → checkAccessToken() → 放行
  │
  ├─ SaOAuth2Util.getClientToken(tokenValue) 查找 ClientToken
  │    │
  │    └─ 找到 → 获取 clientId → 放行
  │
  └─ clientId 仍为空 → "无效的访问客户端" → 401
```

## 四、互信前提条件

服务间互信要正常工作，必须满足以下条件：

| 序号 | 条件 | 说明 |
|---|---|---|
| 1 | **共享 Redis** | 所有服务必须连接同一个 Redis 实例，Id-Token 和 ClientToken 存储在 Redis 中 |
| 2 | **使用 `feign://` 协议** | Webhook URL 必须以 `feign://` 开头，才能触发 `JbmFeignRequest` 注入认证 |
| 3 | **Nacos 服务发现正常** | `feign://` URL 需要通过 Nacos + LoadBalancer 解析为真实地址 |
| 4 | **Id-Token 未过期** | `sa-token.id-token-timeout` 配置的超时时间内（默认 7 天） |
| 5 | **ClientToken 缓存有效** | 本地 Caffeine 缓存 24 小时，过期后自动重新生成 |

## 五、已知的 401 问题场景

### 5.1 `JbmFeignRequest` 缺少 `Satoken-Id-Token` Header

**问题描述**：`JbmFeignRequest.buildRequest()` 只在 `Authorization` header 中放置了 ClientToken，但**没有**额外添加 `Satoken-Id-Token` header。而接收端 `SaOAuthFilterAuthStrategy` 在 StpUtil 验证失败后，会通过 `req.getHeader(SaIdUtil.ID_TOKEN)` 查找 Id-Token。如果缺少这个 header，Id-Token 验证分支被跳过，最终可能走到找不到 clientId 的逻辑。

**对比**：标准的 Feign 拦截器 `AppPreRequestInterceptor` 同时传递了两个 header：

```java
// AppPreRequestInterceptor.java（标准 Feign 拦截器）
requestTemplate.header(JbmSecurityConstants.AUTHORIZATION_HEADER, ...);
requestTemplate.header(SaIdUtil.ID_TOKEN, SaIdUtil.getToken());  // 额外传了 Id-Token
```

```java
// JbmFeignRequest.java（OkHttp 方式）
httpRequest.header(JbmSecurityConstants.AUTHORIZATION_HEADER, authorization);
// 缺少: httpRequest.header(SaIdUtil.ID_TOKEN, SaIdUtil.getToken());
```

### 5.2 Webhook URL 配置为 `http://` 而非 `feign://`

如果数据库中 `WebhookEventConfig.url` 配置为 `http://10.0.1.98:8010/...` 而非 `feign://jaja-wcs-app/...`，`JbmRequestTemplate.findCustomizeRequest()` 会路由到 `JbmHttpRequest`（不携带认证），请求将不带任何 Token 到达目标服务 → 401。

### 5.3 Redis 不共享

如果两个服务连接了不同的 Redis 实例，Id-Token 无法在服务间传递验证，导致 401。
