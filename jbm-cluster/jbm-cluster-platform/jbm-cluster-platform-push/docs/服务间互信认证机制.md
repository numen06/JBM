# JBM 集群服务间互信认证机制

## 一、当前机制

服务间互信不再使用 Sa-Token Id-Token。当前统一使用标准 OAuth2 Client Credentials JWT：

| Token 类型 | 用途 | 存储位置 |
|---|---|---|
| 标准 OAuth JWT | 用户登录凭证或服务凭证 | Auth 服务签发，下游按 JWKS/公钥校验 |
| Sa-Token Redis Token | 共享 Redis 登录态 | Redis |

下游集成 `jbm-cluster-common-satoken` 后支持三种模式：

| 模式 | 配置 | 说明 |
|---|---|---|
| 混合 | `jbm.security.auth.mode=mixed` | 同时支持 Redis 会话和标准 OAuth JWT，当前集群默认模式 |
| Redis | `jbm.security.auth.mode=redis` | 只信任共享 Redis 中的 Sa-Token 登录态 |
| OAuth | `jbm.security.auth.mode=oauth` | 只信任 Auth 服务签发的标准 JWT，适合外部/轻量资源服务 |

## 二、调用方

内部服务通过 Feign/请求拦截器携带：

| Header | 内容 |
|---|---|
| `Authorization` | 用户 Bearer Token，存在用户上下文时透传 |
| `X-Internal-Authorization` | OAuth2 Client Credentials Bearer JWT |
| `X-Internal-Service` | 调用方服务名 |

## 三、接收方

`SaOAuthFilterAuthStrategy` 的认证顺序：

1. 优先检查当前 Sa-Token 登录态。
2. `oauth/mixed` 模式下校验标准 OAuth JWT，并绑定到 Sa-Token 上下文，供 `@SaCheckLogin` 和权限注解使用。
3. `redis/mixed` 模式下校验 Redis 中的 Sa-Token/OAuth2 历史 token。
4. 内部服务调用使用 `X-Internal-Authorization` 的标准 JWT 做互信。

## 四、排错点

| 场景 | 检查项 |
|---|---|
| OAuth-only 下游 401 | 是否配置 `jbm.security.auth.mode=oauth`、`jbm.security.standard-jwt.enabled=true`、`issuer/audience/jwks-uri` |
| Redis 模式 401 | 是否连接同一个 Redis，Sa-Token token-name/prefix 是否一致 |
| 内部服务 401 | 是否携带 `X-Internal-Service` 和 `X-Internal-Authorization: Bearer <jwt>` |
| 注解权限失败 | JWT claims 中是否包含 `sub/user_id/permissions/roles`，或 Redis session 中是否有 `loginUser` |
