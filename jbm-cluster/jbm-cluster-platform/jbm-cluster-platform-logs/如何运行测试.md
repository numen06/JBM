# 如何运行业务日志测试

## 测试类说明

`BusinessLogCompleteTest` 是一个标准的 Spring Boot 测试类，包含以下测试方法：

### 完整测试
- `testAll()` - 运行所有测试（包含模式一和模式二的所有场景）

### 模式一：从本地文件上传
- `testMode1_UploadFromLocalFile()` - 测试所有从本地文件上传的场景
- `testUploadCompileLogFile()` - 单独测试上传编译日志文件
- `testUploadApplicationLogFile()` - 单独测试上传应用日志文件
- `testIncrementalUploadLog()` - 单独测试增量上传日志

### 模式二：业务实时写日志
- `testMode2_RealTimeLogging()` - 测试所有实时写日志的场景
- `testRealTimeOrderProcessLog()` - 单独测试订单处理流程日志
- `testRealTimeDataSyncLog()` - 单独测试数据同步任务日志
- `testRealTimeBatchProcessLog()` - 单独测试批处理任务日志

## 运行方式

### 方式1：在IDEA中运行

1. 打开 `BusinessLogCompleteTest.java` 文件
2. 右键点击测试类或测试方法
3. 选择 "Run 'BusinessLogCompleteTest'" 或 "Run 'testAll()'"

运行单个测试方法：
- 右键点击具体的测试方法（如 `testMode1_UploadFromLocalFile()`）
- 选择 "Run 'testMode1_UploadFromLocalFile()'"

### 方式2：使用Maven命令运行

```bash
# 运行所有测试
mvn test -Dtest=BusinessLogCompleteTest

# 运行指定测试方法
mvn test -Dtest=BusinessLogCompleteTest#testAll

# 运行模式一的测试
mvn test -Dtest=BusinessLogCompleteTest#testMode1_UploadFromLocalFile

# 运行模式二的测试
mvn test -Dtest=BusinessLogCompleteTest#testMode2_RealTimeLogging

# 运行单个场景测试
mvn test -Dtest=BusinessLogCompleteTest#testRealTimeOrderProcessLog
```

### 方式3：使用Gradle运行（如果项目使用Gradle）

```bash
# 运行所有测试
./gradlew test --tests BusinessLogCompleteTest

# 运行指定测试方法
./gradlew test --tests BusinessLogCompleteTest.testAll
```

## 测试前提条件

### 1. OpenObserve服务已启动

确保OpenObserve服务正在运行：

```bash
# 检查OpenObserve是否运行
curl http://localhost:5080/api/v1/health

# 或使用Docker启动OpenObserve（如果未安装）
docker run -d \
  --name openobserve \
  -p 5080:5080 \
  -e ZO_ROOT_USER_EMAIL=admin@example.com \
  -e ZO_ROOT_USER_PASSWORD=admin123 \
  public.ecr.aws/zinclabs/openobserve:latest
```

### 2. 测试配置文件

测试使用 `src/test/resources/bootstrap-test.yml` 配置文件。

**重要配置项：**

```yaml
# OpenObserve配置（必须配置）
open-observe:
  url: http://10.100.10.65:5080  # 修改为您的OpenObserve地址
  organization: default
  stream: business_log_test
  username: admin
  password: admin123

# Nacos配置（测试环境已禁用）
spring:
  cloud:
    nacos:
      config:
        enabled: false  # 测试环境禁用，使用本地配置
      discovery:
        enabled: false  # 测试环境禁用服务发现

# 其他配置
server:
  port: 0  # 随机端口，避免冲突

jbm:
  cluster:
    token-type: memory  # 测试环境使用内存token
```

**如果您的OpenObserve配置不同，请修改 `bootstrap-test.yml` 文件。**

### 4. 相关依赖已正确引入

确保 pom.xml 中包含：
```xml
<dependency>
    <groupId>com.jbm</groupId>
    <artifactId>jbm-framework-autoconfigure-openobserve</artifactId>
</dependency>
```

## 常见问题

### 1. 测试失败：Failed to load ApplicationContext

**错误信息**：
```
Caused by: org.springframework.beans.factory.NoSuchBeanDefinitionException: 
No qualifying bean of type 'jbm.framework.boot.autoconfigure.openobserve.OpenObserveTemplate'
```

**原因**：测试配置文件不正确或OpenObserve配置缺失

**解决**：
1. 确保 `src/test/resources/bootstrap-test.yml` 文件存在
2. 检查OpenObserve配置是否正确：
   ```yaml
   open-observe:
     url: http://10.100.10.65:5080  # 确认URL正确
     username: admin
     password: admin123
   ```
3. 确认依赖 `jbm-framework-autoconfigure-openobserve` 已正确引入
4. 如果使用了Nacos，确保测试环境中已禁用：
   ```yaml
   spring:
     cloud:
       nacos:
         config:
           enabled: false
   ```

### 2. 测试失败：无法连接到OpenObserve

**原因**：OpenObserve服务未启动或配置错误

**解决**：
- 检查OpenObserve是否正在运行：`curl http://10.100.10.65:5080/api/v1/health`
- 验证 `bootstrap-test.yml` 中的URL、用户名、密码
- 尝试访问 OpenObserve UI：http://10.100.10.65:5080
- 如果使用Docker，确保容器已启动：`docker ps | grep openobserve`

### 3. 测试超时

**原因**：某些测试包含 `Thread.sleep()`，可能需要较长时间

**解决**：
- 在IDEA中增加测试超时时间
- 或者运行单个快速测试方法

### 4. 日志文件不存在

**原因**：测试尝试读取实际的日志文件，但文件不存在

**解决**：
- 测试会自动创建模拟日志文件
- 如果需要测试真实日志文件，确保 `logs/` 目录下有日志文件

## 查看测试结果

测试完成后，可以：

1. **查看控制台输出**：包含详细的测试步骤和结果

2. **通过API查询日志**：
```bash
# 获取logId后查询完整日志
curl http://localhost:8080/businessLog/getFullContent/{logId}

# 查询总行数
curl http://localhost:8080/businessLog/getTotalLines/{logId}

# 查询最后10行
curl "http://localhost:8080/businessLog/getByLineRange/{logId}?startLine=1&endLine=-1"
```

3. **在OpenObserve UI中查看**：
   - 访问 http://localhost:5080
   - 进入 Logs 菜单
   - 选择 `business_log` 流查看数据

## 自定义测试

可以在测试类中添加自己的测试方法：

```java
@Test
public void testMyCustomScenario() {
    // 创建日志
    CreateBusinessLogForm createForm = new CreateBusinessLogForm();
    createForm.setModule("我的模块");
    createForm.setOperation("我的操作");
    createForm.setContent("测试内容");
    
    String logId = businessLogService.createLog(createForm);
    
    // 追加日志
    AppendBusinessLogForm appendForm = new AppendBusinessLogForm();
    appendForm.setLogId(logId);
    appendForm.setContent("追加的内容");
    businessLogService.appendLog(appendForm);
    
    // 验证结果
    String fullLog = businessLogService.getLogByIdFullContent(logId);
    log.info("完整日志: {}", fullLog);
}
```

## 建议的测试顺序

1. 首先运行 `testMode1_UploadFromLocalFile()` - 测试文件上传功能
2. 然后运行 `testMode2_RealTimeLogging()` - 测试实时写日志功能
3. 最后运行 `testAll()` - 完整功能测试

这样可以逐步验证各个功能模块，更容易定位问题。
