# JBM 安全合规改造 — 前后端分离破坏性变更说明

> 文档版本：与 JBM 7.2 安全合规后台改造同步  
> 适用对象：前端开发、测试、联调人员  
> 后端范围：`jbm-cluster` / `jbm-framework` / `jbm-util`

---

## 1. 改造背景

为满足安全审计要求，后端已完成以下能力：

| 编号 | 要求 | 后端状态 |
|------|------|----------|
| 1 | 口令 90 天定期更换，到期前提醒，满 90 天强制改密 | 已实现 |
| 2 | 敏感信息传输加密 | 部分实现（Captcha POST + RSA 可选；需 HTTPS + 前端配合） |
| 3 | 系统内敏感信息脱敏展示 | 已实现（响应层） |
| 4 | 连续登录失败 5 次锁定 5 分钟 | 已实现（修复原 Redis 计数失效） |
| 5 | 文件上传失败明确提示 | 已实现（文案优化） |
| 6 | 操作/登录日志只读，不可删除 | 已实现（登录日志） |
| 7 | 同名账户不可重复添加 | 已实现（修复原静默改绑） |

**本文档只列对现有前端有「破坏性」或「行为变化」的项**，以及前端必须/建议的改造动作。

## 4. 响应内容变化（字段名不变，值变了）

### 4.1 脱敏规则

后端在 JSON **序列化输出**时对以下字段脱敏（数据库存储仍为完整值）：

| 字段 | 脱敏规则 | 示例 |
|------|----------|------|
| `realName` | 保留首字 | `张三` → `张*` |
| `mobile` | 保留前 3 + 后 4 | `15112342213` → `151****2213` |
| `email` | 保留首字符 + 域名 | `a@b.com` → `a***@b.com` |

涉及实体：`BaseUser`、`JbmLoginUser`（带 `@SensitiveField` 注解的字段）。

### 4.2 受影响接口（举例）

| 模块 | 接口 | 影响 |
|------|------|------|
| 用户管理 | `POST /baseUser/pageList`、`/list`、`/model` | 列表/详情显示脱敏值 |
| 用户管理 | `GET /baseUser/getUserInfoById`、`getUserByPhone` | 同上 |
| 当前组织用户 | `GET/POST /current/org/users/**` | 同上 |
| 登录 | OAuth2 登录成功 `result`（`JbmLoginUser`） | `mobile`、`realName` 为脱敏值 |

### 4.3 未脱敏例外

| 接口 | 说明 |
|------|------|
| `GET /current/user/account` | 当前登录用户查看**本人**账户信息，完整展示 |

### 4.4 前端改造

- [ ] **用户管理列表/详情**：按脱敏值展示，不要假设能拿到完整手机号/姓名
- [ ] **个人中心**：不要用登录接口返回的 `JbmLoginUser.mobile/realName` 展示本人信息，改调 `GET /current/user/account`
- [ ] **编辑表单回显**：不要把 `151****2213` 当作真实值提交更新
- [ ] **复制手机号、导出、搜索高亮**：需产品确认是否允许管理员看完整信息（当前后端未提供管理员明文接口）

## 5. 登录相关行为变化

### 5.1 密码 90 天过期 — 登录被拒绝

**触发条件**：`LoginType.PASSWORD` 密码登录，校验账号密码成功后，检查 `base_account.password_update_time`（无则回退 `update_time`）。

| 距上次改密天数 | 行为 |
|----------------|------|
| &lt; 80 天 | 正常登录 |
| 80 ~ 89 天 | 登录成功，响应 `extra` 带到期提醒（见 5.3） |
| ≥ 90 天 | **登录失败**，不签发 Token |

**失败文案**：

```text
密码已过期，请先修改密码后再登录
```

**前端改造**：

- [ ] 登录页识别该错误，引导用户进入改密流程（非泛化「用户名或密码错误」）
- [ ] 设计「未登录状态下过期改密」或「改密后重新登录」流程（需与产品确认）
- [ ] 注意：短信/第三方登录当前**未**做同样过期校验

### 5.2 登录失败锁定 — 从失效变为真实生效

**原行为（Bug）**：失败次数写死为 0，几乎不会锁定。  
**现行为**：

| 配置项 | 值 |
|--------|-----|
| 最大失败次数 | 5 次 |
| 锁定时长 | 5 分钟 |
| Redis Key | `login_error:{username}` |

**失败未达上限时**（密码登录示例）：

```text
密码输入错误{N}次
```

**达到上限或锁定期间**：

```text
密码错误次数过多，帐户锁定5分钟
```

（短信登录对应 `sms.code.retry.limit.*` 文案。）

**前端改造**：

- [ ] 区分「密码错误」「剩余次数」「账户已锁定」
- [ ] 锁定时展示倒计时（5 分钟）或禁用登录按钮
- [ ] 登录成功后后端会清空失败计数，无需前端处理

### 5.3 登录成功 — 密码到期提醒（增量字段）

当密码登录且距上次改密 ≥ 80 天时，成功响应增加：

```json
{
  "success": true,
  "code": 200,
  "message": "...",
  "result": { "userId": 1, "username": "...", "mobile": "151****2213", ... },
  "extra": {
    "passwordExpireDays": 7,
    "passwordNeedChange": false
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `extra.passwordExpireDays` | number | 距离强制改密剩余天数 |
| `extra.passwordNeedChange` | boolean | 当前为 `false`（未满 90 天） |

**前端改造**：

- [ ] 读取 `extra.passwordExpireDays`，弹窗/横幅提醒用户尽快改密
- [ ] 老前端不读 `extra` 不影响登录，但合规场景建议实现

### 5.4 改密接口（刷新过期时间）

用户改密成功后，后端会更新 `base_account.password_update_time`：

| 接口 | 方法 |
|------|------|
| `/current/user/rest/password` | GET |
| `/current/user/update/password` | POST |

改密成功后用户可重新登录（若此前因过期被拒）。

## 6. 账号注册 — 重复账号报错

**原行为**：`register` 在账号已存在且 `userId` 不同时，会**静默改绑**到新用户。  
**现行为**：直接失败。

**错误文案**：

```text
账号 [xxx] 已存在，不可重复添加
```

用户名重复（`BaseUser`）原有校验不变：

```text
用户名:xxx已存在!
```

**前端改造**：

- [ ] 注册/第三方绑定失败时展示明确提示
- [ ] 不要按「注册成功」处理此前依赖静默覆盖的流程

## 7. 文件上传 — 白名单与接口拆分（P1）

文档服务（`jbm-cluster-platform-doc`）将**图片**与**办公文档**上传分离，并改为**白名单**校验（叠加危险扩展名黑名单兜底）。

### 7.1 接口说明

| 接口 | 方法 | 用途 | 允许类型 |
|------|------|------|----------|
| `/upload/image` | POST | **新增**，上传图片 | 默认 `jpg/jpeg/png/gif/webp/bmp/ico`，可配置扩展 |
| `/put` | POST | 上传随机文档 | 办公文档白名单（见下） |
| `/upload` | POST | 上传分组文档（`group` 可选） | 办公文档白名单 |
| `/baseDocGroup/uploadByToken` | POST | Token 组内上传 | 办公文档白名单（路径不变） |

**办公文档默认白名单**：`pdf`；Word 系 `doc/docx/txt/dot/wps/wpt/dotx/docm/dotm`；Excel 系 `xls/xlsx/xlt/xlsm/xltx/xltm/csv/et`；PPT 系 `ppt/pptx/pptm/pps/ppsm/potx/potm/dpt/dps`。可通过配置扩展（见 7.2）。

请求参数与改造前一致：`file`（必填）、`group`（`/upload`、`/upload/image` 可选）。

### 7.2 白名单配置（`jbm.doc.upload`）

配置项位于 `bootstrap.yml` 或 Nacos `doc.properties`：

| 配置项 | 说明 |
|--------|------|
| `jbm.doc.upload.document-allowed-extensions` | **覆盖**默认文档白名单（配置后仅以该列表为准） |
| `jbm.doc.upload.image-allowed-extensions` | **覆盖**默认图片白名单 |
| `jbm.doc.upload.additional-document-extensions` | 在默认文档白名单上**追加**（如 `log`、`zip`、`json`） |
| `jbm.doc.upload.additional-image-extensions` | 在默认图片白名单上追加 |

**开箱默认**：`jbm-cluster-platform-doc` 的 `bootstrap.yml` 已预置常见追加类型（日志、压缩包、音视频、证书、CAD、字体等；图片含 svg/heic/avif/psd 等）。生产环境可在 Nacos `doc.properties` 按环境增删。

示例（仅追加少量类型，无需列出全部 Office 类型）：

```yaml
jbm:
  doc:
    upload:
      additional-document-extensions:
        - log
        - zip
        - json
```

图片追加示例（在默认 jpg/png 等基础上增加 svg、tiff）：

```yaml
jbm:
  doc:
    upload:
      additional-image-extensions:
        - svg
        - tiff
```

图片全量覆盖示例：

```yaml
jbm:
  doc:
    upload:
      image-allowed-extensions:
        - jpg
        - png
        - webp
```

危险扩展名（`jsp`、`exe` 等）仍由框架黑名单强制拦截，**不可**通过配置放开。

### 7.3 破坏性变化

| 场景 | 影响 |
|------|------|
| 原通过 `/put` 或 `/upload` 上传 **图片** | **将失败** → 改调 `POST /upload/image` |
| 原上传 **zip/log** 等 | 默认已通过 `additional-document-extensions` 放开；可按环境在 Nacos 调整 |
| 上传办公文档/PDF | 路径不变，仍在白名单内 |
| 类型不允许 | 返回 `不允许上传该类型文件`（与改造前文案一致） |

### 7.4 其他上传错误文案（非破坏性）

| 场景 | 示例提示 |
|------|----------|
| 超过 Spring 上传大小限制 | 文件大小超过限制（10MB），请压缩后重试 |
| Multipart 解析失败 | 文件上传失败，请检查网络连接或文件大小后重试 |
| Minio/IO 超时 | 文件存储服务异常 / 上传超时，请稍后重试 |

### 7.5 前端改造

- [ ] **图片上传**：所有经 `/put`、`/upload` 传图的调用改为 `POST /upload/image`
- [ ] **文档上传**：继续用 `/put`（无分组）或 `/upload`（带 `group`）
- [ ] **日志/压缩包等**：由运维在 `jbm.doc.upload` 配置，前端无需改接口
- [ ] 上传失败：展示后端返回的具体 `message`

## 8. Captcha 手机验证码 — 非破坏性（GET 保留）

### 8.1 现有前端（GET）— 无需改动

| 接口 | 方法 | 参数 |
|------|------|------|
| `/captcha/pcode` | GET | `phone`、`vcode`（Query） |
| `/captcha/pcode/verify` | GET | `phone`、`vcode`（Query） |

逻辑与改造前一致，仅 Java 侧标记 `@Deprecated`。

> **合规注意**：GET 方式手机号仍在 URL 中，抓包可见明文。满足审计需迁移 POST。

### 8.2 推荐新方式（POST，可选）

| 接口 | 方法 | Body |
|------|------|------|
| `/captcha/pcode` | POST | 见下表 |
| `/captcha/pcode/verify` | POST | 见下表 |

**Request Body**（`PhoneCaptchaForm`）：

```json
{
  "phone": "15112342213",
  "vcode": "图形验证码",
  "appKey": "可选，phone 为 RSA 密文时必填"
}
```

**RSA 加密流程**（与密码登录一致）：

1. `GET /captcha/pkey?appKey=xxx` 获取公钥  
2. 前端用公钥加密手机号  
3. POST body 中 `phone` 传密文，`appKey` 传应用标识  

`resolvePhone` 逻辑：若 `phone` 已是合法手机号则按明文处理；否则按 RSA 密文 + `appKey` 解密。

## 9. 数据库变更（部署注意）

Flyway 脚本：`jbm-cluster-platform-center/src/main/resources/db/migration/V1__security_compliance.sql`

```sql
ALTER TABLE base_account ADD COLUMN password_update_time DATETIME NULL;
UPDATE base_account SET password_update_time = update_time WHERE password_update_time IS NULL;
CREATE UNIQUE INDEX uk_base_account_identity ON base_account (account, account_type, domain);
```

- center 服务启动时自动执行  
- 若库中已有重复 `(account, account_type, domain)`，唯一索引创建会失败，需先清理数据

## 12. 联调验证用例

| 用例 | 预期 |
|------|------|
| 连续 5 次错误密码 | 第 6 次提示锁定 5 分钟 |
| 正确密码登录 | 失败计数清零 |
| `POST /baseAccountLogs/deleteByIds` | 404 |
| `POST /baseUser/pageList` | `mobile` 为 `151****2213` 格式 |
| `GET /current/user/account` | 本人手机号为完整值 |
| 密码超过 90 天未改 | 登录失败，提示改密 |
| 密码 80~89 天未改 | 登录成功，`extra.passwordExpireDays` 有值 |
| 重复注册已存在账号 | 返回「账号已存在，不可重复添加」 |
| 经 `/upload` 上传 jpg 图片 | 失败，提示不允许上传该类型文件 |
| 经 `/upload/image` 上传 png | 成功，返回 docPath |
| 经 `/upload` 上传 pdf/docx | 成功 |
| 上传 zip 压缩包 | 在默认 `additional-document-extensions` 配置下应成功 |
| 上传超大文件 | 提示文件大小超过限制 |
