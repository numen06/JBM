# JBM 多租户 IoT 集成标准测试规范

版本：1.2
适用范围：JBM 统一身份/租户/应用/权限与 IoT 业务平台的集成、回归和发布验收。

## 1. 测试目标

本规范验证的不只是页面可打开，而是以下事实始终成立：

1. 用户只能用 JBM 统一账号进入已开通的应用；IoT 不维护第二套登录身份。
2. `appId`、`tenantId`、`projectId` 各自只表达应用、数据所有租户和项目范围，任何两者不得互相代替。
3. 菜单权限和 API 动作权限一致，隐藏菜单不能替代后端拒绝。
4. 运营方只有在“自身角色允许”和“客户委托允许”同时成立时，才能访问客户授权的项目。
5. 共享类型/型号只产生目录引用权，不产生客户项目、设备、告警或遥测读取权。
6. 浏览器、API、异步任务、缓存、时序库、消息和导出使用同一数据范围。

## 2. 场景与参与方

测试故事如下：客户 A 创建东园区和西园区，并在两个项目下分别接入路灯。客户 A 只把东园区委托给运营方 B 的精确账号；无关租户 C 不参与任何共享。运营方顶部必须显示数据来源租户，所有业务列表服从当前项目。

| 平台根管理员 | 默认组织 | `admin` | break-glass | 管理应用、租户、角色；不作为日常代运营账号 |
| 客户 A 管理员 | 双园区租户 / `1873154222409215215` | `iot_reg_owner_a_0811` | `iot_admin` | 管理 A 的东、西园区和设备 |

### 2.1 身份准备规则

验收身份必须模拟真实业务流程，不允许用 SQL、数据库客户端或 seed 脚本直接创建用户、绑定角色或创建委托来冒充页面验收：

1. 新用户从 IoT 公开“用户注册”入口开始，经过验证码后自动建立普通租户、应用开通、默认 owner role 和首次登录；页面不得出现“创建租户账号”或运营角色选项。
   - 注册页不展示个人/组织类型，也不要求组织名称；注册只创建未认证账号及技术隔离空间。
   - 个人认证与组织认证只能在登录后的独立身份认证流程中选择，注册参数不得提前决定认证结论。
   - 本地调试验证码 `9999` 只有在后端显式启用 `dev-bypass-enabled` 且前端以调试模式构建时才允许；生产验收必须使用真实验证码。
2. 第二个成员从 JBM 用户管理页由有权主体创建/邀请，并在页面绑定当前应用角色。
3. 角色模板、菜单、按钮和成员角色从平台角色/菜单/用户页面由平台运营管理员主动授权；注册页和租户用户不能自行取得 `iot_operator`。
4. 跨租户委托由数据所有方登录“委托运营”页面，输入精确运营账号后创建或撤销；同一运营租户的其他账号不得继承。
5. 数据库只能做注册结果、唯一约束和审计字段的只读核验；不能作为验收写入通道。

seed 身份只可用于自动化单元测试和故障排查，不计入“从 0 注册”浏览器验收。

## 5. 租户与项目隔离用例

每一种业务资源都必须执行同一组用例，资源至少包括项目、区域、网关、设备、规则、告警、工单、遥测和操作记录。

| 编号 | 身份与动作 | 预期 |
| --- | --- | --- |
| ISO-01 | 客户 A 管理员列出资源 | 可见东、西园区；不见 C |
| ISO-02 | 客户 A 只读用户读取东、西园区详情 | 200；写操作 403 |
| ISO-03 | 运营方 B 不带目标租户访问 | 只落到 B 自己租户，不得默认看到 A |
| ISO-04 | B 指定 A 且访问东园区 | JBM 委托通过，IoT 项目归属通过，只返回东园区数据 |
| ISO-05 | B 指定 A 且访问西园区 | 403/404；项目选择器、列表、数量、详情均不得泄露西园区 |
| ISO-06 | B 猜测 A 的西园区设备主键 | 403/404；响应不得透露设备是否存在 |
| ISO-07 | C 指定 A 或猜测 A 设备主键 | 403/404；无委托绝不跨租户 |
| ISO-08 | 把设备从东园区移到西园区 | B 立即失去当前设备访问；旧遥测仍保留事件发生时 projectId=1 |
| ISO-09 | 新建 P503 | B 默认不可见；客户必须显式扩展委托 |
| ISO-10 | 聚合统计/分页/导出 | 计数和内容均只覆盖授权项目，不能先全租户聚合再在前端过滤 |

## 6. 委托生命周期用例

- 新授权：生效时间前拒绝，到达生效时间后允许。
- 到期：`validTo` 后立即拒绝，缓存、导出任务和订阅同步失效。
- 撤销：新请求立即拒绝；正在执行的控制任务按任务安全策略取消或拒绝下一阶段。
- 权限交集：客户授予 operate，但 B 自身只有 read 时仍拒绝写；B 有 operate，但客户只授予 read 时也拒绝写。
- 项目交集：委托只含 501 时，无论请求体、旧请求头或前端参数如何伪造，都不能扩大到 502。
- 审计：成功和拒绝日志都记录 `userId / actorTenantId / resourceTenantId / appId / delegationId / projectId / requestId`。

## 8. 异步与旁路隔离

以下链路不得只依赖 HTTP 控制器过滤：

- 定时任务、Worker、规则引擎、告警通知、OTA、批量控制；
- Redis 键和缓存标签；
- TDengine/时序库标签和聚合查询；
- Kafka/RabbitMQ/MQTT 主题及消费者上下文；
- 对象存储路径、文件下载、临时签名 URL；
- 搜索索引、报表、导出文件和 WebSocket/SSE 订阅。

每条消息/任务至少携带 `resourceTenantId + projectId + requestId`；代运营任务还携带 `actorTenantId + delegationId`。消费者执行前重新校验授权有效性，禁止把生产者的前端判断当作永久授权。

## 10. 自动化与发布门禁

每个 PR 至少通过：

```text
静态检查 / 单元测试
JBM tenant + app + role 作用域测试
IoT read / operate / admin API 权限测试
列表 + 详情 + 写入的跨租户反例
委托 projectIds 正反例与撤销/过期
共享目录所有权和版本测试
关键异步链路隔离测试
真实域名浏览器冒烟
```

发布阻断条件：

- 任一资源缺少 `tenant_id` 或项目归属不可解析；
- 详情、批量、导出或异步链路绕过统一范围解析器；
- 只测试菜单隐藏，未测试后端 403/404；
- 数据迁移存在未归属或冲突记录；
- 浏览器出现白页、OAuth 回调失败或关键控制台异常；
- 原运行中的 IoT 容器被替换，或集成镜像未使用独立版本标签。
